## External handoff contracts

The following branches are reserved for outside contributors. Each branch
starts from the current `native-mvp` HEAD. A contributor may add new files in
their listed area, but must not edit `native/src/main.cpp`,
`native/src/native_renderer.cpp`, `native/include/native_renderer.h`, or
protocol files unless the contract explicitly lists them. The integrator will
adapt the final APIs on `native-mvp`.

### H1: animation decoder (`handoff-animation`)

**Goal:** decode TF2 animation MDLs and produce deterministic local bone
tracks without changing the existing bind-pose loader.

**Allowed:** `native/src/model_loader.cpp`, `native/include/model_loader.h`,
new `native/src/animation_decoder.*`, new `native/include/animation_decoder.h`,
animation probes, and animation evidence documents. `native/CMakeLists.txt`
may be changed only to register new decoder/probe files.

**Required deliverables:** a decoder API that returns explicit status and
failure reason; sequence-to-animdesc binding; RAWROT/RAWROT2 and ANIMROT
handling with documented confidence; parent-chain local-to-model transforms;
loop/once sampling; and fixtures or commands using real TF2 VPK animation MDLs.

**Acceptance:** real Scout/Soldier animation data parses without out-of-range
bones; bind pose remains unchanged; repeated sampling at the same tick is
bitwise deterministic; malformed offsets are rejected; a probe shows a child
bone moving when a parent rotates. Do not claim Euler order or position scale
as verified without an engine reference or a visual comparison artifact.

### H2: ViewModel and first-person (`handoff-viewmodel`)

**Goal:** resolve `v_*.mdl` assets, attachments, sequences, handedness and
independent viewmodel FOV while keeping world-camera code untouched.

**Allowed:** new `native/src/viewmodel.*`, new
`native/include/viewmodel.h`, `model_loader.*`, ViewModel probes and docs, plus
the minimum CMake registration. Do not edit `main.cpp` or renderer draw code.

**Required deliverables:** explicit v-model asset resolution from VPK/loose
files, attachment lookup, sequence metadata, left/right hand transform,
viewmodel FOV normalization (default 80), and a failure state for missing
companions. The output must be a renderer-neutral transform/mesh request.

**Acceptance:** real TF2 v-model companions resolve; invalid paths fail safely;
FOV input is clamped; attachment names and sequence labels are preserved; a
probe covers both right- and left-hand transforms.

### H3: entity model instances (`handoff-entity-models`)

**Goal:** map decoded entity model references to cached MDL assets and produce
instance transforms for players, weapons and static props.

**Allowed:** new `native/src/entity_model.*`, new
`native/include/entity_model.h`, `model_loader.*`, resolver probes and docs.
Do not edit `demo_header.*`, `main.cpp`, or `native_renderer.*`; submit any
needed protocol or renderer API as a written interface request instead.

**Required deliverables:** normalized model path resolution, per-entity cache
keys, origin/angles/team/skin extraction contract, missing-asset fallback,
and a bounded instance list that cannot grow with malformed entity indices.

**Acceptance:** real POV and SourceTV samples resolve known model paths; cache
keys are stable; malformed and unknown paths produce diagnostics rather than
crashes; no duplicate load occurs for identical model/checksum pairs.

### H4: world materials (`handoff-world-materials`)

**Goal:** advance the current safe BSP fallback toward Source-like materials.

**Allowed:** `bsp_map.*`, `vmt_material.*`, VTF/material helpers, material
probes, and material evidence docs. Do not edit entity, animation, audio, or
main-loop files.

**Required deliverables:** per-face lightmap UV/sample metadata, cubemap face
discovery and a six-face sampling contract, bump/selfillum parameter mapping,
and explicit Water reflection/refraction capability states. Any approximation
must be labeled as such.

**Acceptance:** real BSP/VPK resources parse without oversized allocations;
synthetic six-face VTF ordering is proven; missing lightmaps/cubemaps use a
stable fallback; probe output distinguishes `source-equivalent` from
`average-intensity` and `approximate-2d`.

### H5: audio and effects (`handoff-audio-effects`)

**Goal:** complete tick-aligned weapon, footstep, Uber, projectile and common
particle events without playing voice/admin broadcast audio.

**Allowed:** audio/effects modules, `temp_effect_probe`, audio/effects probes,
and docs. Do not edit `main.cpp` or renderer shader code.

**Required deliverables:** sound index to VPK WAV resolution, event category
filtering, delayed tick scheduling, spatial attenuation data, and a bounded
TempEntity/PCF event representation. Audio tests must use a null or explicitly
selected unused device.

**Acceptance:** fixture events preserve tick order and pause/reverse behavior;
voice, announcer and music are filtered; missing/corrupt WAV/PCF resources do
not abort playback; no test emits audio on the default device.

## Handoff procedure

1. Fork or clone the public repository and check out the named branch from
   `native-mvp`.
2. Keep all work in that branch/worktree. Do not commit generated `build/`
   output, TF2 Demo files, VPK payloads, or credentials.
3. Every commit must include a focused probe result and list exact real-resource
   paths used. A green compile alone is not acceptance.
4. Open a pull request against `native-mvp` or send the branch and commit IDs.
   The main integrator will rebase-free inspect the diff, rerun the full native
   build and gates, resolve conflicts, and only then merge.
5. A task is not complete when its branch builds; it is complete only when the
   acceptance evidence and known limitations are recorded.
