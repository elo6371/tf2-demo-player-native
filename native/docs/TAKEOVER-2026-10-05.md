- Win32 + D3D11 hardware initialization with 11.0 and WARP fallback.
- Real TF2 VPK/VTF/VMT/BSP resource loading with bounded reads and missing
  resource fallback.
- PacketEntities baseline, delta, preserve, enter, leave and remove replay;
  entity snapshots can drive the observer focus by Demo tick.
- Three POV scans have zero entity and TempEntity reconstruction errors:
  `73.dem`, `autorecord_2026-05-14_16-09-14.dem`, and
  `autorecord_2026-09-30_23-06-57.dem`. `cp_snakewater_final1` is a separate
  SourceTV zero-failure fixture; `koth_bagel_rc13.dem` is intentionally not
  green and remains the primary protocol regression.
- Basic BSP world geometry, perspective camera, depth buffer, fallback entity
  markers and decoded projectile/particle diagnostic lines are rendered.
- Bind-pose model mesh and GPU bone constant upload are wired. The model draw
  binds the shared MVP constants and reports `SkinningReady` only after a
  validated bone upload.
- Release build, four-sample regression gate, resilience gate, and model pose
  self-test pass locally.
- Native UI import state controller is integrated: `.dem` open/drop, header and
  index review, TF2-root/BSP availability, cancel/error recovery, playback
  command state, tick clamping, HUD/mute/fullscreen state, and UI probe.
- Win32 controls are now integrated for opening a Demo, drag-and-drop, import
  review, play/pause, stop, single-tick stepping, reverse, and timeline seek.
  The UI probe and Release build pass after this integration.
- Native acceptance gate is integrated and locally passes WARP smoke, process
  lifetime, metrics validity, missing-root fallback, optional Demo playback,
  FPS threshold, and working-set threshold checks.
- Entity history diagnostics now distinguish decode gaps from bounded-retention
  windows; a scan may report `before-history` for ticks older than the retained
  window and must not be called full random seeking until that is solved.
- Model request normalization and bounded caching are integrated. The cache
  deduplicates stable VPK requests, falls back for missing assets, and caps
  retained requests at 2048. It still feeds diagnostics/fallback markers;
  renderer-neutral model instance caching is now also integrated: identical
  normalized model paths share immutable mesh data under bounded instance and
  vertex budgets. Basic bind-pose entity instance drawing is now connected to
  the D3D11 pass for up to 32 recognized player entities per tick; missing
  models still use markers. Animation matrices, weapon/viewmodel selection,
  and StudioMDL material binding remain unimplemented.
- ViewModel contract probing is integrated, but only the renderer-neutral
  contract is verified; it does not mean a first-person model is drawn.
- VTX packed vertex mappings now use the Source 9-byte layout; a real Scout
  model produces bounded triangle indices and a bind-pose mesh.
- Observer metadata now exposes `setview` and the last `FixAngle` value,
  including its relative flag and three decoded angles. This is not yet a
  per-tick camera track.
- Observer camera samples are now retained in a bounded per-tick track and the
  native playback loop applies absolute `FixAngle` samples to the orbit camera.
  Relative-angle accumulation and full real-Demo visual validation remain open.
- The UI controller has cancellable background import, recent Demo and settings
  persistence. The Win32 controls now expose the recent list, TF2-root chooser,
  settings status, mute, fullscreen, and visible import progress. Detailed
  settings pages, HUD skin import, and polished final layout remain unaccepted.

## External handoff contracts

The following branches are reserved for outside contributors. Each branch
starts from the current `native-mvp` HEAD. A contributor may add new files in
their listed area, but must not edit `native/src/main.cpp`,
`native/src/native_renderer.cpp`, `native/include/native_renderer.h`, or
protocol files unless the contract explicitly lists them. The integrator will
adapt the final APIs on `native-mvp`.

### H1: animation decoder (`handoff-animation`)

**Goal:** decode TF2 animation MDLs and produce deterministic local bone
tracks without changing the existing bind-pose loader.

**Allowed:** `native/src/model_loader.cpp`, `native/include/model_loader.h`,
new `native/src/animation_decoder.*`, new `native/include/animation_decoder.h`,
animation probes, and animation evidence documents. `native/CMakeLists.txt`
may be changed only to register new decoder/probe files.

**Required deliverables:** a decoder API that returns explicit status and
failure reason; sequence-to-animdesc binding; RAWROT/RAWROT2 and ANIMROT
handling with documented confidence; parent-chain local-to-model transforms;
loop/once sampling; and fixtures or commands using real TF2 VPK animation MDLs.

**Acceptance:** real Scout/Soldier animation data parses without out-of-range
bones; bind pose remains unchanged; repeated sampling at the same tick is
bitwise deterministic; malformed offsets are rejected; a probe shows a child
bone moving when a parent rotates. Do not claim Euler order or position scale
as verified without an engine reference or a visual comparison artifact.

### H2: ViewModel and first-person (`handoff-viewmodel`)

**Goal:** resolve `v_*.mdl` assets, attachments, sequences, handedness and
independent viewmodel FOV while keeping world-camera code untouched.

**Allowed:** new `native/src/viewmodel.*`, new
`native/include/viewmodel.h`, `model_loader.*`, ViewModel probes and docs, plus
the minimum CMake registration. Do not edit `main.cpp` or renderer draw code.

**Required deliverables:** explicit v-model asset resolution from VPK/loose
files, attachment lookup, sequence metadata, left/right hand transform,
viewmodel FOV normalization (default 80), and a failure state for missing
companions. The output must be a renderer-neutral transform/mesh request.

**Acceptance:** real TF2 v-model companions resolve; invalid paths fail safely;
FOV input is clamped; attachment names and sequence labels are preserved; a
probe covers both right- and left-hand transforms.

### H3: entity model instances (`handoff-entity-models`)

**Goal:** map decoded entity model references to cached MDL assets and produce
instance transforms for players, weapons and static props.

**Allowed:** new `native/src/entity_model.*`, new
`native/include/entity_model.h`, `model_loader.*`, resolver probes and docs.
Do not edit `demo_header.*`, `main.cpp`, or `native_renderer.*`; submit any
needed protocol or renderer API as a written interface request instead.

**Required deliverables:** normalized model path resolution, per-entity cache
keys, origin/angles/team/skin extraction contract, missing-asset fallback,
and a bounded instance list that cannot grow with malformed entity indices.

**Acceptance:** real POV and SourceTV samples resolve known model paths; cache
keys are stable; malformed and unknown paths produce diagnostics rather than
crashes; no duplicate load occurs for identical model/checksum pairs.

### H4: world materials (`handoff-world-materials`)

**Goal:** advance the current safe BSP fallback toward Source-like materials.

**Allowed:** `bsp_map.*`, `vmt_material.*`, VTF/material helpers, material
probes, and material evidence docs. Do not edit entity, animation, audio, or
main-loop files.

**Required deliverables:** per-face lightmap UV/sample metadata, cubemap face
discovery and a six-face sampling contract, bump/selfillum parameter mapping,
and explicit Water reflection/refraction capability states. Any approximation
must be labeled as such.

**Acceptance:** real BSP/VPK resources parse without oversized allocations;
synthetic six-face VTF ordering is proven; missing lightmaps/cubemaps use a
stable fallback; probe output distinguishes `source-equivalent` from
`average-intensity` and `approximate-2d`.

### H5: audio and effects (`handoff-audio-effects`)

**Goal:** complete tick-aligned weapon, footstep, Uber, projectile and common
particle events without playing voice/admin broadcast audio.

**Allowed:** audio/effects modules, `temp_effect_probe`, audio/effects probes,
and docs. Do not edit `main.cpp` or renderer shader code.

**Required deliverables:** sound index to VPK WAV resolution, event category
filtering, delayed tick scheduling, spatial attenuation data, and a bounded
TempEntity/PCF event representation. Audio tests must use a null or explicitly
selected unused device.

**Acceptance:** fixture events preserve tick order and pause/reverse behavior;
voice, announcer and music are filtered; missing/corrupt WAV/PCF resources do
not abort playback; no test emits audio on the default device.

### H6: native product UI (`handoff-ui`)

**Goal:** turn the diagnostic Win32 shell into a usable standalone Demo player
without reintroducing Electron, WebGL, browser, or Node.js dependencies.

**Required product surfaces:**

- Opening screen with `Open Demo`, drag-and-drop for `.dem`, recent Demo list,
  TF2 root selection, and a clear missing-root/error state.
- Import review showing Demo filename, map, recording type (POV/SourceTV when
  known), tick count, duration, required BSP/model/audio assets, missing
  resources, and a cancellable import action.
- Player shell with play/pause, stop, one-tick and one-second stepping, speed
  control, reverse, timeline scrubber, current tick/time, camera reset, mute,
  fullscreen, and a diagnostics drawer. Every control must have a keyboard
  equivalent and a disabled state when no Demo is loaded.
- HUD layer with health, ammo, team, tick and recording indicators. Include a
  HUD visibility toggle, safe-area control, and an importable theme/layout
  directory. The default theme should follow the supplied `m0rehud-5.8`
  resource layout, but missing HUD files must fall back to built-in labels.
- Settings page for Performance/Standard quality, FOV (default 80), VSync,
  audio device and volume, TF2 root, input bindings, camera presets, and
  persistence through the existing settings store.
- Export entry point that reports a precise disabled reason until an exporter
  exists; it must not pretend that a screenshot/video export succeeded.

**Allowed:** new `native/src/native_ui.*`, new `native/include/native_ui.h`, UI
probes and evidence documents, the window creation/message-routing portions of
`native/src/main.cpp`, and the minimum CMake/settings-store registration.

**Forbidden:** entity/protocol decoding, BSP/VMT/VTF parsing, model/animation
decoding, audio scheduling, D3D11 shader and draw code. The UI must consume
renderer-neutral state and command callbacks rather than reaching into those
modules directly.

**Acceptance:**

1. A clean launch shows the opening screen; opening a valid Demo reaches the
   import review and then the player without command-line arguments.
2. Dropping a Demo, cancelling import, selecting a missing BSP, selecting a
   missing TF2 root, and opening a corrupt/truncated Demo all produce recoverable
   messages and leave the window usable.
3. Player controls update the existing playback state and title diagnostics;
   timeline scrubbing never reports a tick outside the indexed range.
4. HUD can be hidden, theme import can be rejected safely, and the default HUD
   remains readable at 1280x720 and 2560x1440 with Windows DPI scaling.
5. Settings persist across restart, quality/FOV changes take effect, and no UI
   test opens the default audio device or starts a Demo implicitly.
6. A focused UI probe records the state transitions and exact failure messages;
   a Release build and existing native regression gates remain green.

**Implementation order:** opening/import state machine, player controls and
timeline, settings, HUD, diagnostics/export states, then DPI/fullscreen polish.
Do not block the first usable build on final TF2 pixel matching; label visual
approximations and leave the renderer integration behind the existing APIs.

## Handoff procedure

1. Fork or clone the public repository and check out the named branch from
   `native-mvp`.
2. Keep all work in that branch/worktree. Do not commit generated `build/`
   output, TF2 Demo files, VPK payloads, or credentials.
3. Every commit must include a focused probe result and list exact real-resource
   paths used. A green compile alone is not acceptance.
4. Open a pull request against `native-mvp` or send the branch and commit IDs.
   The main integrator will rebase-free inspect the diff, rerun the full native
   build and gates, resolve conflicts, and only then merge.
5. A task is not complete when its branch builds; it is complete only when the
   acceptance evidence and known limitations are recorded.
