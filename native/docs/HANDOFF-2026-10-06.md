## 工作区规则

- 每个接手者从当前 `51f6f0d` 或明确记录的主线提交创建独立分支。
- 可以修改既有代码，但不得直接写主线工作区。
- 实体、渲染、BSP、音频、UI 改动分开提交；超过五个文件拆成可审查提交。
- 动画/ViewModel 对话可修改其负责模块，但接入 `main.cpp`/renderer 前必须给出兼容性说明。
- 主线整合者先运行 `git merge-tree`，再 cherry-pick，禁止用合并预演污染工作区。

## 强制验收清单

每个交付必须在 Markdown 中填写：

- [ ] commit ID、基线 commit、修改文件清单。
- [ ] 真实资源路径和 Demo 文件名。
- [ ] 可复制的配置、构建、运行命令。
- [ ] 原始构建/运行输出，不写“已测试”代替证据。
- [ ] 已验证、未验证、已知限制和失败原文。
- [ ] 目标 exe 的绝对路径、启动/退出状态和音频设备状态。
- [ ] 至少一个针对变异或错误输入的反向验证。
- [ ] 说明是否可以运行；不能运行时明确阻塞原因和下一步。
