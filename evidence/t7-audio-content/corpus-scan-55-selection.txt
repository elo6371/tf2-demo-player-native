# How the 55 recordings in corpus-scan-55.jsonl were selected (2026-10-16)
#
# The corpus is \/demos: 1687 *.dem files, 44 163 051 737 bytes (41.13 GiB),
# including two recordings the T3 round already pinned.
#
# A whole-corpus pass was started and abandoned, and the rate is the reason. The
# 55-recording run below covers 1 134 705 010 bytes (1082.14 MiB, mean 19.7 MiB
# per recording) and took about 20 min 20 s of wall clock, i.e. roughly 0.89
# MiB/s. At that measured rate the whole corpus extrapolates to about 13 hours
# -- and the first attempt at it produced no flushed per-demo record in three
# minutes, which is consistent with that. A gate cannot run for 13 hours, and
# T7 asks which inputs contain a category, not for an exhaustive count, so the
# selection rule below replaces the exhaustive pass. The extrapolation is an
# extrapolation: it is quoted as a feasibility argument, never as a count.
# Every number that is used as evidence comes from the 55 recordings actually
# scanned, and each of those is bound to its own size and sha256.
#
# The rule, applied to every *.dem header in the corpus (1687 headers parsed, 136
# distinct maps): keep every recording whose map name contains one of
# 'event' / 'mvm' / 'circus' / 'asteroid' / 'doomsday'. That is the whole
# non-standard game mode population -- the Halloween maps, MvM, and the two maps
# that carry round-end music -- which is where a music event could plausibly be
# emitted through SVC_Sounds. 22 maps, 55 recordings.
#
