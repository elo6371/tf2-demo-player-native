WHY THIS FILE EXISTS RATHER THAN PUTTING THE TIP SHA IN THE REPORT
-----------------------------------------------------------------
The delivery report has to pin "the final commit", but a file committed in X
cannot contain X's own sha (self-reference), and any tip sha written today goes
stale the moment one more doc commit lands. So the report pins the two anchors
that never move (A = product, B = evidence+report) and delegates the tip to
`git log -1`, i.e. to Git itself. The invariant that makes this safe is stated
above: everything after A is documentation and evidence only.

THE MERGE TARGET IS A, NOT THE TIP
----------------------------------

commit that carries the product change is A. B onward carries evidence, the
report and this pin file. Merging A alone is equivalent to merging the product
code at the tip; nothing after A touches a build input.
