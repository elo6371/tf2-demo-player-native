#!/usr/bin/env bash
# hostlock.sh v2.2 (2026-10-20) -- serialized host access: builds, product
# launches, captures, mutation suites and audio-device runs are one-at-a-time.
#
# v1 had no queue and starved an agent. v2 added FIFO tickets; v2.1 fixes two
# defects found in the first rollout: dead tickets blocked the head (no
# heartbeat), and a reservation could not hand the lock to its owner because a
# non-reserved ticket stayed at the head. Now every waiter touches its ticket
# each poll (dead tickets are pruned after 3 min), and when the Lead has
# reserved a window the reserved owner may take the lock out of queue order
# while every other owner backs off until the reservation expires. The reserved
# owner consumes the reservation when it acquires, so the window closes itself.
#
# USAGE
#   bash hostlock.sh status
#   bash hostlock.sh run <owner> <cmd...>
#   bash hostlock.sh acquire <owner> [timeout_s]
#   bash hostlock.sh release <owner> [--force]
#   bash hostlock.sh reserve <owner> [ttl_s]     # Lead only
#   bash hostlock.sh unreserve
#   bash hostlock.sh break <owner>
set -uo pipefail
ROOT=/d/TF2_Native_Worktrees/_shared
LOCK=$ROOT/host.lock
QUEUE=$ROOT/queue
RESERVATION=$ROOT/reserved
STALE=${HOSTLOCK_STALE_SECONDS:-3600}
mkdir -p "$QUEUE"

now() { date +%s; }
# v2.3: how long since the holder last touched its heartbeat, in seconds.
# Used by status and by break so a takeover can say what it displaced.
heartbeat_age() {
  local f="$LOCK/start"
  [ -e "$f" ] || { echo 0; return 0; }
  local ts
  ts=$(stat -c %Y "$f" 2>/dev/null || echo 0)
  [ "$ts" -gt 0 ] || { echo 0; return 0; }
  echo $(( $(now) - ts ))
}

void parseTickList(const std::string& list, std::vector<std::int32_t>& out) {
  std::size_t start = 0;
  while (start <= list.size()) {
    const auto comma = list.find(',', start);
    const auto token = list.substr(start, comma == std::string::npos ? comma : comma - start);
    if (!token.empty()) out.push_back(static_cast<std::int32_t>(std::strtol(token.c_str(), nullptr, 10)));
    if (comma == std::string::npos) break;
    start = comma + 1;
  }
}

# Playback throughput must not be a correctness threshold

## Symptom

The integrated render gate reported `pov history observations: 889 < 1000` even
though the ViewModel animation input, sequence changes, model pairing, refusal,
and accepted-pose checks were valid.

## Context

`viewmodel-animation-check.sh` replays a real demo and reads a cumulative
`observations` counter. Startup latency, hidden-window state, audio, and render
throughput change how many snapshots are processed before the requested capture
point. One run later produced 1804 observations from the same input.

## Root cause

The gate treated a performance-dependent sample count as a semantic invariant.
The real correctness conditions were already checked independently: observations
exist, sequence values change, distinct sequences are present, and each refusal
or accepted pose has the expected fields.

## Verified solution

Keep only `observations >= 1` and retain the semantic assertions. Launch product
captures with `--hidden-window --audio-disabled` so the gate is quiet and audio
device timing cannot affect the run.

## Evidence

  `889 < 1000`.
- After fix: `viewmodel-animation-check.sh` returned rc=0 and
  `VIEWMODEL-ANIMATION=PASS`; the quiet run measured POV observations 1047 and
  history observations 1552.

## Prevention

Do not pin throughput counters in correctness gates. Pin semantic state and use
explicit timing controls for pixel captures; use separate performance tests for
throughput.
