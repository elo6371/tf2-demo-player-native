== 3. 结论（对修复的含义） ==
(1) 旧代码把 firstPacketTick 当 server origin 是错的：S1 的 firstPacketTick 是 10252（signon
    entry tick），与 server tick 10320 毫无关系；旧代码 sceneTick = 10252 + playback，
    在 playback=0 时查询 10252，比实体历史起点（74481）早 6 万多 tick。
(2) 正确关系是逐包表，不是线性偏移：S1 有 11 处 server tick 跳号、S5 有 4 处，说明包被丢弃。
    table[0]=10320 (S1) / 56148 (S5)，table 末项 S1=74671、S5=129277。
(3) 第一个数据包不一定带自己的 svc_NetTick：S1 的首个数据包 entry=1 自身无 NetTick，
    但 networkTick 从 signon 的 NetTick 继承（10320），所以 server tick 已知且为 10320，
    不是推测；S5 的首个数据包自带 NetTick=56148。规则 6 满足：值来自持久 networkTick，
    没有做任何“偏移相加”。
(4) 视图样本（cmdinfo）用 entry tick 排序，signon 样本必须排除：S1 signon 样本 3 条
    (entry 10252 起)，数据样本从 1 开始严格递增；S5 同理。修复后 view_ordered=1。
(5) 实体历史从 74481 (S1) / 129210 (S5) 起才有 checkpoint：所以 playback 0 查询 10320
    得到 before-history，这是 A6 负控的依据；而 30319 查询得到 checkpoint（states=2048），
    56148 也是 checkpoint。快照状态 0=available, 1=checkpoint 都表示“有对象”，
    A3/A6 必须接受两者，不能用 “available” 单值。
(6) SourceTV demo 的 76 字节 cmdinfo 区全为 0（S1 tick 601/20000/60000、S5 tick 600/601/602
    逐字节检查；探针 camera_origin=0,0,0）。所以 SourceTV demo 无法证明相机眼位；
    A5 改用 POV demo P1（pl_frontier_final, autorecord_2026-09-10_14-04-13.dem，
    ticks=5118，cmdinfo tick 600 原点 1784.664,-3594.817,239.965）。
