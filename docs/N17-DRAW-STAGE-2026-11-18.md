## 1. 老卡验收项「Scout 身上的深灰斜板」：不是绘制缺陷（不改）

原验收：`bar_count.py` 的条状物 mask（自然帧 max 通道 ≤95 且 max−min ≤14 且 id 帧 R=91/G=0/B=0）
从 1149 px 降到 0，且人形其余不变。

**逐条排除：**

1. **来源同一次 draw。**`p3/range.log` 明细里该实体只有 8 条 range，
   条状物落在 ordinal 97：
   `range: ordinal=97 blended=0 slot=0 body=0 key=models/player/scout.mdl#1098120898#0#body=0
   vertexStart=0 vertexCount=8490 instanceStart=117 instanceCount=1 translucent=0 textured=1 dbg=0`。
   用 `--entity-range-skip 97` 拿掉这一条：条状物 gone=805（基本消失），但 Scout 同时缺腿缺臂
   ⇒ 它是**整个躯干 run**，条状物与躯干不可分离。
2. **像素 id 证明是同一个玩家 draw。**`p1/natural.bmp` + `p1/id.bmp` 采样：
   条状物 1149 px **全部** id=(91,0,0)；Scout 红衣服 884/921 px 也是 (91,0,0)。
   不是额外实体、也不是另一个材质批次。条状物自然色 top5：
   (54,46,41)×94、(54,44,41)×66、(54,46,46)×61、(49,42,38)×54、(55,47,41)×52。
3. **不是被姿态拉长的三角形。**新诊断 `TF2_NATIVE_UV_DUMP=<cacheKey 子串>`（在
   `uploadEntityModelMesh` 里逐 run 量边长/UV 面积）：
   scout slot=0 `verts=8490 tris=2830 maxEdge=5.15 longEdges(>8u)=0`；
   其余 run maxEdge 2.36–5.69，全部 <8u。没有跨躯干的超长边。
4. **不是 UV 涂抹/跨图集采样。**同一诊断：scout slot=0 `maxUvArea=0.0013 wideUv(>0.02)=0
   nanUv=0 maxU=1.00 maxV=1.00`（最大三角只占图集 0.13%）；slot=1 `maxUvArea=0.0051`；
   只有两只眼球 slot=2/3 有 `wideUv=3 maxUvArea=0.0243`（眼球本来就跨 UV，正常）。
5. **不是任何 bodygroup 变体。**探针新增 `model-slot-bodypart` 打印，scout 的 5 个 bodypart：
   `0 engineer base=1 count=1 / 1 hat base=1 count=2 / 2 headphones base=2 count=2 /
   3 shoes_socks base=4 count=2 / 4 dogtags base=8 count=2`。
   强制 body=1/2/4/8 分别只让条状物 mask 少 73/36/58/**0** px（换的是帽子/耳机/鞋/军牌），
   条状物本体一格没动。
6. **不是绑定姿态开关造成的。**`--entity-bind-pose-mutation`（强制不吃蒙皮、停在 bind pose）：
   条状物仍在（gone=724/1149，残 425 暗 px），只是形态从"外伸板"变成"贴胸带"。
   ——**关键证据**：bind pose 下它是贴在胸口的深色斜带，带金属亮边/扣头；自然帧里同一条带子
   被弯腰姿态推到躯干左缘之外、盖住身后的 Engineer。

**结论：这是玩家模型自带的斜挎肩带（bandolier / satchel strap）几何，不是绘制缺陷。**
旁证：同一帧里 blue Engineer 躯干上有同款斜挎带+扣，暗部主色 (35,29,26)×319、(32,25,18)×95，
与 Scout 的 (54,46,41) 同皮革色系；`scout.mdl` 的 9 条 LOD0 descriptor（`entity_model_probe
--dump-model-slots`）合计 23442 index = 我们 8 条 range 之和，其中 bp0/model0/mesh0 正好 8490
（主身体网格，material `scout_red`），没有任何"额外附件网格"。

**因此本卡不动绘制层。**能删掉这些像素的唯一开关 `--entity-range-skip 97` 会同时删掉整个躯干，
验收里的"条状物消失、人形其余不变"在绘制层无法同时成立。要判定肩带在该姿态下的位移是否与 TF2
一致，属于动画/骨骼层（task-7 模型卡），需要 TF2 同 tick 参考帧；本卡不给结论。

## 2. 老卡验收项「武器/挂件 attach 一直是 0」

**定案：不是缺陷，是开关默认关闭。**

- `scene: weaponAttach on=0 held=0 drawn=0` / `attach: coverage requested=0` 是 `--player-weapon-attach`
  默认 off 的结果。`native/src/main.cpp:3519-3525` 注释写明两条理由：
  ① 持武器会替换同一武器实体的独立实例，改默认会无声改变每个带枪玩家的画面；
  ② 它是 A/B 对照，off 必须保持既有 gate 的基线帧。
- 打开后一切正常：`--player-weapon-attach on` →
  `scene: weaponAttach on=1 held=17 drawn=17 poseMissing=0 overBudget=0 refused=0`；
  `attach: coverage requested=17 resolvedFromWorld=11 uploaded=6 refused=0`；
  与 `p3/range.bmp` 像素 diff **534 px**，bbox 561,114,743,313（枪出现在手上）。
- 另一处"unknown"读数同理：HUD 的 `attachment=unknown / bodygroup=unknown` 只由 standalone
  `--model` 的 inspection 填（`main.cpp:8575-8577`），不跑 `--model` 就恒 unknown，
  与 demo 绘制无关。

⇒ 保持默认 off；需要看武器帧时显式加 `--player-weapon-attach on`。

## 3. 老卡验收项「bodygroup 选择器没接通」：已接通并算术正控

**缺陷确认**：玩家实体原来只在 `mapStaticProp` 优先级下才构建带 bodygroup 的 material run，
`PlayerBody` 路径拿到的是不带 body 信息的 run，`m_nBody` 从来没被消费。

**修复（`native/src/main.cpp:5846-5870` 区域）**：

```cpp
const bool bodygroupsWanted =
  prepared.priority == tf2::native::EntityMeshPriority::WorldProp
  || prepared.priority == tf2::native::EntityMeshPriority::PlayerBody;
bool materialRunsBuilt = tf2::native::ModelLoader::buildMaterialRuns(
  request.inspection.metadata, prepared.runs, runsError, bodygroupsWanted);
if (!materialRunsBuilt && bodygroupsWanted) { /* 回落不带 bodygroup，并 trace
  "gpu: entity mesh bodygroups-unavailable path=... reason=..." */ }
```

玩家 draw 侧（`main.cpp:13297-13335`）从实体属性表读 `m_nBody`
（`rankPropertyCandidates(bodyState, "m_nBody")`，非正数按 0），
渲染侧 `native_renderer_entity.cpp:585-601` 用 `instance.body` 选桶
（`created.body = selectedBody; created.key = bucketKey;`）。

选择公式在 `native/include/native_renderer.h:157-167`：

```cpp
bool selectedForBody(std::uint32_t body) const {
  return bodyCount == 0 || (bodyBase != 0 && (body / bodyBase) % bodyCount == bodyModel);
}
```

（注意：这是**除法取模**语义，不是 Source 位域的右移；`bodyBase==0` 时该 run 只在
`bodyCount==0` 下被画。body=0 恒选 model0，所以历史帧不受影响。）

**算术正控**（`p6/cmp_ranges.py`：`p3/range.log` vs `TF2_NATIVE_BODY_MUTATION=2` 的 `p6/body2list.log`）：

| 职业 | ranges | 顶点 | 差 |
| --- | --- | --- | --- |
| engineer | 4 → 4 | 22314 → 31662 | **+9348 = 10410 − 1062** |
| scout | 8 → 7 | 23442 → 21900 | −1542 |
| pyro | — | — | −792 |
| demo | — | — | −1488 |
| sniper | — | — | −690 |
| heavy / medic | — | — | 0 |

`+9348` 精确等于 engineer bp2 model1（`models/player/engineer/engineer_mech_hand`，10410）
减 model0（1062）——只有选择器真的被消费才会有这个数。全场景 318 → 309 ranges。

**像素正控**：`TF2_NATIVE_BODY_MUTATION=2` 帧与默认帧 diff **488 px**，
bar 区域只有 36 px 变暗（换的是二代 body 件，条状物无关）；
body=1/4/8 分别 556/1330/416 px。trace 侧 `gpu: entity bodyMutation forced=192 body=2`
（96 draw/帧 × 2 帧）。

## 4. 老卡验收项「缺 textureView 的 range 被静默跳过」

原来 `native_renderer_frame.cpp` 里对没有 textureView 的 range 直接 `continue`，
既不画也不记账，于是"少了哪一条"只能靠人肉对账。

**修复**：新增具名计数 `Renderer::entityModelUntexturedRangeCount()` /
`entityModelFirstUntexturedRange()`（`native_renderer.h:944-948`、成员 2132-2133），
在 `setEntityModelInstances` 每帧清零并记录首个缺纹理 range 的 key；
抓帧时输出：

```
scene: entityRanges ranges=317 texturedRanges=316 texturedInstances=61 \
       skinnedInstances=32 meshes=73 textures=1043
scene: entityRanges untextured=1 first=models/weapons/c_models/c_ubersaw/c_ubersaw_xmas.mdl#2112110215#0#body=1#slot=2#verts=2676#entity
```

原先口头传的"312/313"在新构建里是 **1 条**，并已具名：`ubersaw_xmas` 的 slot=2
（2676 顶点的一把近战武器，缺材质不影响玩家本体）。

## 5. 老卡验收项「FOV 推导没有自证」

`native_renderer_frame.cpp:483-498`：世界纵向 FOV 由
`sourceHorizontalFovToVertical(settings_.worldFov)` 得出（`native/include/world_fov.h:11`，
按 Source 的 4:3 参考口径换算），near 由 `max(worldHorizontalScale * 4mapUnits, 1e-6)` 得出，
far 保持 100 box units。capture 时打印一行自证：

```
capture: fov source=settings.worldFov horizontal=90.0000 vertical=73.7398 \
         rule=sourceHorizontalFovToVertical aspect=1.856094 near=0.0006 far=100.0000
```

`native/tools/camera_probe.cpp:525-529` 的独立自检：90 → 73.7398、75 → 59.8404，
与引擎输出一致（`p7/default.log`）。
