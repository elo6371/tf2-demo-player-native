## 2. Build fixes (the code had never been compiled)

The first compile failed twice; both causes are recorded here because they are properties of `main.cpp`,
not of this step's design:

1. **D-90 build-identity refusal** — `native/cmake/gen-build-stamp.cmake:293` refuses to hash a tree with
   untracked compile inputs, naming `include/target_identity.h`. Fixed by `git add`-ing the new header; the
   file is part of this commit anyway.
2. **C2065** `main.cpp:1221` `g_followArgumentRejected` used before its definition — fixed with one
   `extern` declaration above `followQueuePush`, the single definition stays in the counter block.
3. **C1061** (blocks nested too deeply) reported at `main.cpp:4060` — the overflow was **not** the new
   per-frame block but the CLI `else-if` ladder: the four new `--follow-*` rungs pushed the chain past
   MSVC's limit. The file already documents this ceiling at `main.cpp:3440-3443` and moves flags out of the
   ladder for exactly this reason. The four rungs were therefore replaced by
   `bool followConsumeArgument(LPWSTR*, int, int&)` called immediately before the ladder; the ladder is now
   **byte-identical to HEAD** (530 lines, 117 top-level rungs, `IDENTICAL: True`).

**Consequence to remember:** the ladder has **no headroom** again. The next flag added *inside* it will
reproduce C1061; consume it before the ladder instead.

Build: `bash build-target.sh tf2_demo_native` → exit 0, no error lines; the only `main.cpp` warnings are the
pre-existing C4244 pair of `_wtof` assignments (now `:3583-3587`) and two pre-existing C4457/C4456.

## 3. A8 — the guardrail, and why its stated form had to be fixed

**Finding (measured, not argued).** The design's A8 asked for byte-identical camera trace lines against a
reference run. That is unachievable by any build, because the trace volume follows frame pacing, and pacing
follows machine load. Two runs at `--playback-speed 8` on the same demo and tick:

| run | exe | trace lines | `povQueries` | elapsed |
|---|---|---|---|---|
| step-3 reference, 2026-11-14 23:10 | `90f781b5` | 75,799 | 1429 | 242.9 s |
| this exe, 2026-11-15 10:09 | `6d15c566` | 154,899 | 2932 | 163.1 s |

The 12.4 MB vs 25.3 MB trace difference is *pacing*, not code. This repo already wrote down the rule for
camera traces: `docs/N12-ACCEPTANCE-2026-11-15.md:398` — "断言不得回读 povApplied 的整数行数做等价比较
（每次运行帧数不同）；按 tick 归键比对". A8 is therefore executed **keyed by tick**, exactly as N12 §17.4 does,
and every assertion below is either keyed or byte-wise on something that is genuinely deterministic.

## 4. What is deliberately NOT done here

- Camera precedence is untouched: in a POV demo the eye still wins over the pinned target
  (`cameraEffect=pov-eye-wins`), so selecting a player does not yet change the picture. That is step 2's
  separate decision, as the design requires.
- `serial` has no data source yet: it prints 0 = unknown, and `gone-index-reused` is encoded but unreachable.
- A1–A7 (command semantics) are not exercised by A8; they need the probe/step-2 harness.
