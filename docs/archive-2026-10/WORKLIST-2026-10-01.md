每项工单一个 worktree + 一个分支，**不要多人在同一棵树里改**：

```bash

git worktree add "D:/TF2 Demo 播放器/work/wt-<工单号>" -b <分支名> desktop-ui-ugc-d
```

  应当看到 **`09e25bb`**（2026-10-01 21:30 的 HEAD）。看不到就先别改 —— 说明基线不对。

### 三条铁律

1. **只碰「允许改」列出的文件。** 碰了别的就是冲突，合并不进来。
2. **新判据必须先能红。** 写完做一次变异，证明它会失败。凡「全绿」，先变异再相信。
3. **读数写文件，不写注释。** 证据进 `docs/evidence/<topic>.md`，机器可读读数进 `release-<topic>/*.json`（后者已被 gitignore）。

### 交付长什么样

一次提交（或按 功能/仪器/文档/证据 拆几次）+ 三条命令的输出：

```bash
npx tsc --noEmit          # 必须 0
npx vitest run            # 不得比基线少通过
node scripts/<你的探针>   # 必须打出可复核读数，且退出码能红
```

## 5. 本机环境坑（不写下来对方一定踩）

### git 事故（本轮真实发生，已修）

**现象**：`git stash push` 与 `git commit` 之后，`D:/TF2 Demo 播放器/work/tf2-demo-player/.git/`
的 `refs/`、`worktrees/`、`objects/pack/*.pack` 整目录消失，`git status` 报 `fatal: not a git repository: (NULL)`。

**根因**：`git commit` 会触发 `gc --auto`，而 `gc` 会剪枝 worktree 管理目录。
本仓有两棵**同名** worktree（`wt-ui-features` 与 `wt-ui-features1`），
其中 `wt-ui-features` 指向已不存在的 `C:/Users/Administrator/Desktop/...`。
剪枝时把**活的那棵**一起剪了 —— 这条坑在项目记忆里记过（「`git worktree prune` 会连活工作树一起清掉」）。

**已做的修复**：

```bash
git config gc.auto 0
git config maintenance.auto false
git config gc.worktreePruneExpire never
# 并删掉 6 个指向已不存在路径的陈旧管理目录，只留 wt-ui-features1
```

**恢复方法**（如果又发生）：回收站里有全套 `$I`/`$R` 对，用
`.scratch/recycle-restore.py`（本机工作目录 `C:/Users/Administrator/WorkBuddy AI/2026-09-30-10-04-44/.scratch/`）
按 `$I` 元数据里的 UTF-16LE 原路径还原。**先跑不带 `--apply` 的试运行。**

**禁令**：

- **永远不要跑 `git worktree prune`。**
- 动 `.git/` 之前先 `cp -r .git/worktrees "D:/TF2 Demo 播放器/work/.git-worktrees-backup-$(date +%s)"`。
- 在 `.git/` 下不要用 `rm -rf`（会被拦并中断命令链），用 Python `shutil.rmtree`。

| **C 盘 100% 满**（剩 ~300 MB） | Chromium 的 crashpad dump / shader cache / 共享内存都在系统 temp，盘满会让 GPU 与渲染进程以 `exit_code=1` 死掉，**表现得像驱动坏了** |
| `vite build` 的 `emptyDir(dist)` 会失败 | 先 `TS=$(date +%s); mv dist "dist.bak.$TS"`，构建后用 Python `shutil.rmtree` 清备份 |
| 探针读哪份产物 | 读 `release/tf2-demo-player.html`，由 `npm run package:single` 产出。**`npm run build` 只写 `dist/`，不刷新单文件产物** —— 会让「变异没进产物」被读成「判据没牙」 |
| Playwright 驱动不了本机 Electron | 用 Node 内置 `WebSocket` 手写 CDP；`Browser.close` 是唯一能关掉 `app.relaunch` 派生进程的手段 |
| `npx vite` 挂起 | Vite 只监听 `::1`，用 `node node_modules/vite/bin/vite.js`；探针用 `node node_modules/vite-node/vite-node.mjs scripts/x.ts` |
| 不采信应用自报数 | 尺寸/时长取 `ffprobe`；画面取 `gl.readPixels`（记得 `flipRows()`）；删除/搬运看文件系统不看返回码 |
| 读 uniform 的坑 | `uHasLightmap` 等是**最后一次写入值**；`uBones` 的 uniform 名是 `uBones[0]`，按裸名匹配永不命中且静默 |

## 6. 合并契约（主控视角）

主控接受一个分支的条件，缺一不可：

1. 分支基线是 `desktop-ui-ugc-d`，且**只改了「允许改」清单里的文件**。
2. `npx tsc --noEmit` 退出码 0；`npx vitest run` 通过数不少于基线。
3. 新增判据**有变异证据**（写明变异内容 + 变红了几条）。
4. 探针读数落成文件（`docs/evidence/*.md` + `release-*/json`），**不是**只写在提交信息里。
5. 报告里区分「实测」「推断」「本机无法构造」三类，不得混写。

不接受的形态：改了禁止改的文件；判据全绿但没做过变异；把「本机测不了」写成「已验证」。

### 6.1 合并流程（主控执行）

> **2026-10-01 18:44 更新（必读）**：本节旧版第 2 步是
> `git merge --no-commit --no-ff <分支名> && git merge --abort`。
> **这条命令已实测摧毁过一次仓库** —— 它把 `.git/objects/**`、`refs/**`、`worktrees/**`、
> `packed-refs` **连同工作区的 `scripts/` 与 `docs/`** 共 **929 条**一次性搬进回收站
> （详见 `docs/HANDOFF-2026-09-29.md` 的「🔴 事故第二次」）。
> **该步骤已删除，不要再照旧版执行。** 预演一律改用无副作用的 `git merge-tree`。

专项方交付后，主控按顺序做，任一步失败就退回并说明原因：

```bash
# 0) 先整份备份 .git —— 只有 9 MB，代价可忽略；出事时这是唯一可靠的退路
python -c "import shutil,os,time; d='D:/TF2 Demo 播放器/work/.git-backup-%d'%time.time(); \
  shutil.copytree('D:/TF2 Demo 播放器/work/tf2-demo-player/.git', d); print('backup ->', d)"

# 0.5) 清掉残留合并状态 —— 从回收站恢复过 .git 的话，MERGE_HEAD 会跟着复活，
#      之后任何 git commit 都会悄悄产出「假合并」（已真实发生过一次）。
#      git status 不报这件事，必须显式查。
git rev-parse -q --verify MERGE_HEAD && echo "有残留合并状态：先清理再提交"
git rev-parse -q --verify MERGE_MSG  && echo "有残留 MERGE_MSG：先清理再提交"

# 1) 取回并核对边界：只应出现「允许改」清单里的路径
git -C "D:/TF2 Demo 播放器/work/wt-ui-features" fetch "D:/TF2 Demo 播放器/work/tf2-demo-player" <分支名>:<分支名>
git --no-pager diff --name-only desktop-ui-ugc-d...<分支名>   # 三点：以 merge-base 为基准

# 2) 预演合并 —— 无副作用，只写对象，不碰工作区/索引
git merge-tree --write-tree --name-only HEAD <分支名>
#    退出码 0 = 可干净合并；非 0 = 有冲突，此时列表就是冲突文件

# 3) 真合并 —— 不在活工作树上 merge
#    活树上跑 merge 会触发本机的删除守卫/safe-delete shim（这是两次事故的共同路径）。
#    改为：在独立 clone 里合完 → 再 fetch 回活树，或先确认第 0 步的备份已落盘。

# 4) 门禁（见 scripts/merge-gate.mjs）
node scripts/merge-gate.mjs --with-build

# 5) 合并后必查（五项全过才算落地成功）
git worktree list                          # 工作树数量不应减少
git fsck --no-progress                     # 只应出现 dangling，不得有 missing/corrupt
git rev-list --count HEAD                  # 提交数只增不减
git rev-list --parents -1 HEAD             # 合并提交必须正好两个父；普通提交只能一个
sha256sum release/tf2-demo-player.html     # 与门禁记录的产物哈希一致
```

**冲突处理原则**：主控负责解冲突，但**不替专项方改判据**。
若冲突落在专项方的探针/判据文件里，退回给专项方重做，不在主控侧「顺手改一下」。

**预演不是长期许可证**：专项方仍在提交（例如 `e4-luxel-ab` 在预演后又前进了）。
**每次真正落地前都必须重跑第 1、2 步**，不能引用上一轮的 `merge-tree` 结果。

### 6.2 门禁脚本 `scripts/merge-gate.mjs`（主控维护）

一次跑完四件事并给出可复核读数：`tsc --noEmit` / `vitest run` / `package:single` 产物哈希 /
发布验收探针（`--with-probes`）。任一项失败即退出码非 0。

产物哈希是**必须记录**的：两次读数若不是同一份产物，读数不可比。

### 6.3 发布验收（主控收尾）

1. `npx tsc --noEmit` 0；
2. `npx vitest run` 通过数 ≥ 基线（基线数每轮写进交接清单）；
3. `npm run package:single` 产物哈希落盘；
4. NSIS + ZIP 产出；
5. **干净 Windows 安装验收 = 未验证**（本机做不到，见 §3 E1/E5），
   在交接清单里明确标「未验证」，不得写成「已通过」。
