## G6. N05 Sultry 黑点：CPU face 与 GPU pass 的对应方法

**背景**：cp_sultry_b8a 曾出现世界中黑点；最新 COLOR0 窗口未复现。现有三处候选来源（记录编号 849 / 873 / 919）尚未与实际的 GPU draw pass 建立对应。我们怀疑是 CPU 端 face 索引与 GPU 顶点/索引缓冲的提交顺序或绕序在某个 pass 上不一致。

**已有读数**：黑点只在特定窗口/机位出现；COLOR0 readback 最近一次未复现；849/873/919 三个 face 编号来自不同统计口径（面遍历 / draw 批次 / 屏幕点反查），尚未统一。

**要你回答**：
1. 给出一套能把「某个 CPU face」唯一映射到「某次 GPU draw call 的实例+索引偏移」的判据（用我们已有的 trace 字段即可，不要求新探针）：需要记录哪些量、如何自证映射正确。
2. 黑点的三类成因（材质缺、绕序剔除、深度/精度）各用什么最小实验区分；各自的可判别读数是什么。
3. 如果只能在一次运行里取证，优先记录哪 5 个量，为什么。

**必须给的判据**：每条成因一个「看到 X 就是它 / 看到 Y 就排除」的表。
