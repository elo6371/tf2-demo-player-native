# 地图的 3D 天空盒：一次实装、一次独立复验，以及它还没证明的事

2026-11-18 · 世界线（N10 的 `sky_camera` 残项）

## 0. 一句话

`--world-sky-3d on` 现在把地图里 `sky_camera` 那一片空间（bsp 中 `cluster == 天空簇` 的三角形）当作以视点为中心、按 `1/skyCamera.scale` 缩放的 diorama，画在同一个远端平面上；**默认 off**，off 帧与这张卡之前钉死的基准帧逐字节相同。

它解决的是长期挂着 `UNSUPPORTED` 的那一项：只画六面天空盒时，地图作者在 `sky_camera` 附近摆的远山、云墙、城堡剪影全都不出现，玩家看到的天空是「六张图 + 没有远景」；Source 的做法是把那片几何单独再画一遍，这就是所谓 3D skybox。

## 1. 开关与默认

| 项 | 值 |
| --- | --- |
| 命令行 | `--world-sky-3d on\|off` |
| 默认 | **off**（本卡不改任何现有观感） |
| 持久化 | 写进 settings.ini，与其它 `world*` 开关同一套 |
| 生效条件 | 世界几何已上传（`setWorldSky3d` 必须早于 `uploadWorldGeometry`），且地图确实有可用的 sky cluster |
| 无天空簇的地图 | trace 记 `present=0`，pass 直接跳过，不报错 |
| off 时 | 世界构建完全不产生第二份 VB/IB，帧路径与加这个开关之前一致 |

## 3. 打开正例：94 个像素

`--world-sky-3d on` 对同机位的 off 帧：

| 指标 | 值 |
| --- | --- |
| 差异像素 | **94 / 860,784**（0.0109%） |
| 最大通道差 | 53 |
| 全帧平均差 | 0.00417 |
| 包围盒 | x 352–359，y 56–79 |
| 方向 | 全部**变亮**（3D 天空盖住了原本的 2D 天空） |

换算成 run：`sky3d: enabled=1 present=1 scale=16.0 cluster=9 vertices=5103 triangles=1701 batches=2 source=bsp`；off 时 `enabled=0 vertices=0 triangles=0 batches=0`。

### 为什么只有 94 个像素

不是画错了，也不是没画上。这次抓帧的相机 `500 -2240 240` **正好就是地图 `sky_camera` 的原点**——也就是 diorama 的缩放中心。站在缩放中心看 diorama，它和你眼前的主场景几乎完全重合，只有主场景几何「擦」到的那几个像素能看出区别（一条 8×24 的竖条，在天上）。这是最不该看出差别的一个机位，用它做「不影响其它像素」的负控正好，用来判断「画得对不对」是错的。

判断「管线到底通不通」用的是另一次诊断：把深度测试真正关掉（见 §5）后，这个 pass 画出 **362,379 像素 = 全帧 42%**（bbox y 266–680），说明顶点缓冲、索引、VS/PS、常量块、mvp 全对；正式状态只画出 94 像素纯粹是深度测试在正常工作。

室内机位 `-373.5 -899.8 443.7`（走廊）：on 与 off 逐字节相同（0 像素差）——被墙挡住的天空不画，符合预期。

## 4. 实现摘要

- **几何**：不另建网格。世界几何上传时按顶点的 leaf cluster 判断是否属于地图天空簇（`BspParser::clusterAt(map, skyCamera.origin)`），把命中的三角形另存一份 VB/IB，并按 sub-batch 切成 range。所以天空盒永远和地图几何同一份坐标、同一份材质。
- **变换**：`mvp = proj * translate(eyeBox - eyeSky) * viewRotation * scale(1/skyCamera.scale)`，其中 `eyeSky = skyOrigin + (eye - skyOrigin) / scale`（scale 本图 = 16）。直观地说：把 diorama 整体平移，使「天空相机在它自己空间里的位置」落到当前视点上，再按 1/16 缩小——于是远处景物的透视与视差和站着不动一样，只是永远不会更近。
- **深度**：顶点着色器输出 `clip.z = clip.w`，把整片天空钉在远平面；深度写关、深度测开（让它被主场景正确遮挡）。
- **着色**：复用世界的 VS/PS 与 input layout，常量块换成中性值（`lightmapFeatures=(1,0,0,0)` 表示「不吃 lightmap」、`envFeatures=0`、`fogParams.w=0` 关雾、`lightDirectionAndMode.w=0` 走无光照路径、N21 的 16 盏灯全给 0），独立第三份 1280 字节常量缓冲，不与主 pass 抢。
- **顺序**：紧接原来的 2D 六面天空盒，在其后、blended batch 之前。画完恢复 index buffer、光栅状态、深度状态和槽位 5。

## 5. 一条值得单独记下来的坑

**`OMSetDepthStencilState(nullptr, 0)` 不是「关深度」。** `nullptr` 表示「用默认深度模板状态」，而默认状态的 `DepthEnable = TRUE`、`Func = LESS`。所以在这条 pass 上用它，等于**照常做深度测试**——早期所有「depth-off」探针都因此看起来像「什么都没画」，让人以为几何或着色器错了，实际是它们全被主场景深度挡住了。

正确的关法是建一个 `DepthEnable = FALSE` 的深度模板状态再设置。换上去之后同样的代码立刻画出 42% 的全帧，问题当场定位。这条教训对以后任何「我要先画、后判遮挡」的 pass 都适用：**在 D3D11 里，「不设状态」不是「关掉状态」。**

## 6. 与 Source 的三条偏差

1. **重叠处多画一次**：3D 天空覆盖到的像素，Source 会跳过 2D 天空盒对应的部分；这里仍然先画 2D 天空盒、再画 3D。结果等价（后画的盖住先画的），代价是那些像素白算一次。
2. **没有独立的 skybox 雾**：`fogParams.w = 0` 直接关雾。Source 给天空盒一支单独的雾参数，远山该被雾化成什么颜色是地图作者调过的；这里远山保持原色，与地面雾的衔接可能偏硬。
3. **不是单 draw**：复用世界 atlas 的 sub-batch，本图切出 2 个 range。三角形数与地图有关，不是常数。

## 7. 这还没有证明什么

- **只测了一张图**（`pl_upward_f12`，天空簇 9）。地图之间的 `sky_camera` 位置、scale、天空簇编号都不同，没有第二张图的正例。
- **只在 sky_camera 原点附近的机位抓过帧**。§3 解释了为什么那个机位看不出差别——真正该看的是「离天空相机很远、抬头能看到远景」的机位，那需要另选机位重抓，本卡没做。
- **blended 顺序没有逐像素归因**：只证明了「on 与 off 差 94 像素且都变亮」，没有证明「这 94 个像素恰好是该被 3D 天空盖住的那 94 个」。
- **trace 的 cluster 值没有断言**：它现在只是打印出来给人看，没有「cluster 必须等于地图声明的 sky cluster」这类守卫。地图换了、bsp 解析漂了，它能悄悄变成别的值。
- 走廊机位的 0 像素是另一台机器的读数，本轮没有复跑。

## 8. 复现

```bash
cd /d/TF2_Native_Worktrees/t105-integrate
bash tools/lockrun.sh t105-sky3d-lead -- bash build-target.sh tf2_demo_native
bash .scratch/sky3d-lead/check.sh          # 三次抓帧 + sha256（脚本未入 git）
python .scratch/n21-lights/iso-diff.py \
  .scratch/sky3d-lead/off.bmp .scratch/sky3d-lead/on.bmp .scratch/sky3d-lead/diff
```

抓帧必须用**相对路径**（绝对 MSYS 路径会让原生 exe 弹模态框假挂起，这是既有教训）；每次运行前从 fixture 重拷 settings，否则上一次的写入会污染下一次。

比较 BMP 时按 `bpp/3` 的步长逐像素比，别把行 stride 和 bpp 混用——本卡复核时我先用自写脚本得 3 像素，换成按 step 3 扁平比较才得到与 PIL 一致的 94，是脚本的 bug 不是产品的问题。
