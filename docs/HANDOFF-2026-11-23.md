### 2.3 构建与铁律
- 构建：`bash build-target.sh <目标...>` 或 `bash build-cmake.sh`，产物在 `native/build-nmake/`。需要 VS2022 + Windows SDK + CMake 3.24+。
- **四条铁律**：
  1. 新源文件**先 `git add` 再构建**：身份戳读 git index，否则 D-90 构建身份检查会拒绝；临时放行用 `TF2_IDENTITY_ALLOW_UNTRACKED=1`。
  2. 改过或还原过的源文件要 **touch**：nmake 只看 mtime。`cp -p` 还原会把旧 mtime 写回去，nmake 就不重编，变异体一直留在二进制里。这是 11-22 大面积假红的主因。
  3. /W4 零警告，七个 /WX 目标不许压警告。`false && x` 写法会触发 C4127 → C2220，变异要写成 `!(x) && (x)`。
  4. 构建和截帧一律走 `tools/lockrun.sh <owner> -- <命令>`。`verify-all.sh` 自己会抢锁，不要再用 lockrun 包它，否则死锁。
- 其它坑：这台机器的 `diff/comm/paste/cmp/join/sha256sum` 是 WinuxCmd 垫片。它读不了 `/dev/fd`，进程替换会被读成 0 字节；`sha256sum` 还会吃掉 stdin。gate 里一律改用实体临时文件，`gate_lint.py` 会拦截这种写法。

## 6. 已经定下的结论（别再重查）

- **第 26 步（player animation pixels）不是回归，判 A+B**：同一 tick 下 base 和 head 截出的覆盖帧逐字节相同。3156 px 那个 PASS 是在静态道具进 entity pass 之前钉的。gate 已改成只在带实体 id 的像素上测。
- **11-22 全链 20 步红的主因**：变异还原用了 `cp -p`、`mutate.sh` 用 `|| continue` 跳过了还原、`false &&` 编译失败、进程替换交给 WinuxCmd 读成 0 字节，再加上录像缺失。逐条归因见 `docs/CHAIN-RED-ATTRIBUTION-2026-11-22.md`。
- **mutate 11-23 的有界重跑**：m2、m7、m8a、m10 都和预期一致；m8b、m11 各出一条 GREEN，原因都在 gate 本身，已修（5.1，未验证）。m10 的“view/model compare”一条按所有者决定**保持 BLOCKED-INPUT 红**，所以 `MUTATION-SUITE` 会一直 FAIL，直到找到一份该读数不为 0 的 POV 录像。
- **minimap 第 6 步帧尺寸不符**：不是 SUNSHINE 覆盖的问题，是隐藏窗口在两次运行之间被改了尺寸。产品侧还没修：固定尺寸时应该拒绝一切改尺寸，WM_SIZE 也要打 trace，留给以后的补丁。
- **P4 普查**：条件位 5 = 无敌（Uber 期间医生 12/12、病人 11/12），默认仍按医疗枪状态判断；位 11 = 暴击；`m_iWeaponState` 只出现过 0/1/2/3；bagel 里没有 Pyro。
- **第一人称**：目视缺陷已修，N18 六项通过。但默认不画手和枪（要 `--viewmodel <路径>` 或 P3 的 `--first-person on`）；开火和换弹的动画在录像里没有自然出现过，P3 的 `--viewmodel-census` 就是用来确认这一点的。
- **武器锚点**早就不是 AABB 中心了：默认按 attachment 对齐，bone 模式也已实现。
