## 4. 语义审查（读代码，逐条）

**成立的部分。** 判定只作用于 `hasMesh && hasDrawSlot` 的 player body，与「画出来的身体」这个命题对齐；每个 checked body 恰好落进一个 status（index / index-mismatch / class-fallback / class-mismatch / unresolved / index-missing-from-precache），`checked = indexResolved + classFallback + unresolved + mismatched` 自洽；`PASS` 要求 `checked>0`，不会空过；`firstMismatch` 只在非 index/非 fallback 时记录，便于定位。

**F1（会误红，建议改）：第三来源被算成 unresolved。** `buildAssetReferenceList` 允许 `m_ModelName`/`m_iszModel` 这类 **server 风格属性**直接给路径（`native/src/demo_header_strtab.cpp:449-560` 的 `findString`）。这种 body 的 `instance.playerClassFallback=false` 且可能没有 `m_nModelIndex`，当前代码会判 `unresolved` → PASS 条件直接失败，尽管它画的是**有名字的**路径。语料里没有玩家发 `m_ModelName`（所以绿跑没暴露），但断言对「第三来源」不是中性的。建议增加 status `property-path`（drawnModel 非空且 request 带路径）并计入 PASS。

**F2（会误红，登记 D-51，本轮不改）：把 index 哨兵值当成 mismatch。** `m_nModelIndex` 可能是 Source 的未设置哨兵（`0`、`0xFFFFFFEA`、`0xFFFFFFFC`；`demo_header_strtab.cpp` 里同名路线就是这么处理的），代码却直接 `static_cast<std::uint16_t>(ownModelIndex)` 查 precache：0 查不到 → `index-missing-from-precache` → 计 Mismatched → 红；负值回绕成 65xxx 也可能意外命中/不命中。应先把 0 与越界值归为「无 index 证据」再走 fallback，而不是记 mismatch。

- 具体行号（t99 patch 后）：`native/src/main.cpp:10380`（`bool hasOwnModelIndex = false;`）、`:10381`（`std::int64_t ownModelIndex = 0;`）、`:10391-10394`（取值，Float 走 `.x`，否则 `intValue`）、`:10395`（`hasOwnModelIndex = true;`）、`:10399`（`if (!hasOwnModelIndex) ++playerModelNoIndex;`）、`:10405`（`static_cast<std::uint16_t>(ownModelIndex)` 查 precache）。
- 建议改法（3 行，纯计数分支，不动产品渲染语义）：在 `:10395` 之后加 `if (ownModelIndex <= 0) { hasOwnModelIndex = false; }`，并在 `:10404` 前对 `ownModelIndex > 0xFFFF` 同样归零。效果：哨兵 0/负值计入 `playerModelNoIndex` 并落到 class fallback 分支，不再可能记成 `index-missing-from-precache` 而误红。
- **本轮未应用，原因（决策记录 D-51）**：判定代码嵌在产品 draw 循环里，现有 fixture（`entity_model_probe --self-test`）只覆盖 `EntityModelResolver::buildInstances`，**无法**构造一个「`m_nModelIndex=0` 的合成 player 走到 `hasMesh && hasDrawSlot`」来证伪这条改动；apply 而不证 = 制造一条没有负控的断言（违反「门禁 PASS 只能支持它断言过的东西」）。要落地需要二者之一：① 把该分类抽成可测纯函数（新头文件/改 main.cpp，需 lead 批准），② 合成一个含哨兵 index 的 demo。本轮不具备，故只留证据与行号。

**F3（语义正确但门禁太弱）：** 草稿的 gate 断言里 `classFallback>=1` 只对 snakewater tick 63000 成立；而本轮实测该 tick `indexResolved=0` —— **只断言 classFallback 的门禁永远碰不到 index 路径**。要防「index 路径被改坏」，必须在 fixture 上断言 precedence（§3），真实 demo 侧的 gate 只能防 fallback 回归。

**F4（可接受，但要写进口径）：** `checked` 是「本帧真正提交的 body 数」，受 `kDrawBudget=96` 与剔除规则影响；它随帧变化，门禁只能断言「>=1 且 verdict=PASS」，不能把某个数字写死。

**F5（未验证）：** 若 `demoNetworkSummary.modelPrecache` 在某 demo 上解析不完整，index 路径会集中报 `index-missing-from-precache` 而红；本轮只跑了一个 demo 的一个 tick，不能宣称该表在所有语料上完整。
