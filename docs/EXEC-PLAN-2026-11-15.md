## 教训六：整树 grep 的 0 命中不能当证据，必须按 src/include/tools 分域查（lead，2026-11-14 20:15 亲测）

## 验收口径：证据形态决定它能证明什么（2026-11-15 19:30 追加）

本轮出现三处「证据本身限制了结论」的情况，统一记为方法学条目，后续报告必须遵守：

1. **B1 只能记 COINCIDENT，不能记 PASS。** 站立时真实 `m_vecViewOffset[2]` = 68.000065，常量 `kSpectatorEyeHeight` = 68.0，**两者差 0.0001 u，低于打印精度**。这条 PASS 对「产品是否读了 viewOffset」**零分辨力**，不得进 PASS 分母。同理：任何「修复前后期望值几乎不变」的样本，都不能当修复证据。
2. **pre-B 的 relay 行不带 `offsetSrc` 尾字段，所以修复前后不能只靠 relay 行对比**（n12-qa 实测 stv-t20000 24 条 / stv-t40000 46 条 relay，`has_tail=no`）。B 卡判定一律用 `scene: camera` 行（每帧都打），**不用 relay 行**——relay 行是 32 u 节流的（`native/src/main.cpp:762` `dx*dx+dy*dy+dz*dz > 1024.0f`），蹲伏 23 u 的修正可能根本不触发重打。
3. **跨时钟量不能直接相减。** 产品 `offsetTick` 是 server tick，oracle `prop_tick` 是 demo playback tick。raw gap 符号在帧间会翻（A1 −172 / A2 −758 / A3 +90），**不得驱动任何判定**；用恒等式 `offsetTick + offsetAge == serverTick − stale`（769/769 行成立）映射到同一空间后，三帧全正（+2375 / +2959 / +1183），方向一致。**raw 与 mapped 必须分两段写，不许合并成「方向不一致」。**
