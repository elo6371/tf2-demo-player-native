## 2 N02 探针路径与失败契约（D38 → CLOSED，D44 新开）

### 2.1 修复前（实测，`n02-matrix.txt`）

| 输入 | world_geometry_probe | world_feature_probe |
|---|---|---|
| TF 相对 + ASCII | rc=0 | rc=2 `cannot read`（只收绝对路径） |
| 绝对 + ASCII | rc=1 `status=missing`（把绝对路径拼进 TF root） | rc=0 |
| 绝对 + 中文 | rc=1 `status=missing` | **rc=3221226505（0xC0000409）空输出** |
| 绝对 + 空格 | rc=1 `status=missing` | **rc=3221226505 空输出** |
| 不存在 | rc=1 + reason | rc=2 + stderr |
| 损坏 BSP | rc=1 报 `status=missing`（原因说不准） | rc=2 `BSP header is invalid` |

**根因**：`std::filesystem::u8path(argv[...])` 把 ANSI（GBK）参数字节当 UTF-8，解码失败抛 `filesystem_error`，无人捕获 → `std::terminate` → 0xC0000409。geometry 侧则是 `root.resolve()` 只认 TF 相对路径。

### 2.2 修复

- 两个探针各加一个**不抛异常**的 `pathFromArgv()`：先试 UTF-8，失败退回 `std::filesystem::path`（Windows 原生窄转换 = ANSI 代码页）。
- geometry：`readAsset()` 对绝对路径先直接读，再走 archive/root.resolve 的旧路径。
- feature：`main` 拆成 `runMain` + 捕获 `std::exception`/`...` 的 `main`，异常一律 `error: <what>` + rc=2；并接受 TF 相对路径（`tfRoot / mapPath` 存在则用）。
- 只构建两个受影响的 probe。

### 2.3 修复后

| 输入 | geometry | feature |
|---|---|---|
| TF 相对 | rc=0 `triangles=71999` | rc=0 `materials=119` |
| 绝对 | rc=0 同上 | rc=0 同上 |
| 中文绝对 | **rc=0 同上** | **rc=0 同上** |
| 不存在 | rc=1 + reason | rc=2 + stderr |
| 损坏 | rc=1 `status=parse-failed` + reason | rc=2 `BSP header is invalid` |

三种写法得到**同一组读数**，失败不再空输出。

`grep -rn "u8path(argv" native/tools/*.cpp` 仍有 **30 处 / 16 个探针**走同一条崩溃路径（`hud_probe`、`install_cli_probe`、`lighting_semantics_probe`、`material_chain_probe`、`material_coverage_probe`、`model_pose_probe`、`model_robustness_probe`、`resource_reachability_probe`、`terrain_blend_probe`、`viewmodel_{contract,material,range}_probe`、`vpk_{integrity,query,readiness}_probe`、`world_material_probe`）。本轮按"一次只修一个证实根因"只动了两个有证据的探针；其余登记 D44，修法即本轮的两段代码。

### 3.1 设置写回：未知键会丢（新缺陷 D45）

N03 要求"暂停/重启后原设置值正确；如发现未知键丢失，另建产品缺陷"。实测：

```bash
cp native/tests/fixtures/gate-settings.ini $OUT/rt.ini
printf 'zzz_future_key=42\n' >> $OUT/rt.ini
tf2_demo_native.exe --settings-file $OUT/rt.ini ... --start-paused --capture-frame $OUT/rt.bmp
grep zzz_future_key $OUT/rt.ini   # 没有
```

- 已知键保留：`preset=1`、`viewModelFov=90` 未变。
- **未知键 `zzz_future_key=42` 被丢弃**，文件被重写成 129 行。
- 影响：降级/回滚时新版本写入的键会被旧版本静默抹掉；门禁把带额外键的 fixture 传给产品时也会被抹。
- 处置：登记 **D45**（P3 数据丢失），不在本轮改产品（设置持久化属另一写域，且要连同"哪些键属于已知集合"一起设计）。
