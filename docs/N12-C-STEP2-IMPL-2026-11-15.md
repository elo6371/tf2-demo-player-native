## 3. 设计决定与理由

### 3.1 backfill 上限 = 2 tick（命名常量）
`kCameraEyeBackfillMaxTicks = 2`。理由（代码注释原文的要点）：一行对应一个数据包，邻行通常只差 1 tick；2 tick 在 66 Hz 约 30 ms，小于一个插值步长（cl_interp ≈ 0.031 s），所以回填来的眼位仍是**本帧**的姿态；更旧的交给快照。**更新的一侧永不用** —— 用未来行等于把猜当读数。

### 3.2 查询用哪个 tick
- POV：`sceneTick`（= `packetServerTicks[sceneRow]`，与 `scene: clock ... serverTick=` 是同一个数、同一来源，构造相等、非独立测量）。
- relay：`g_sceneResolvedServerTick`（身体/快照实际解析到的 tick）。
- tick 未解析（−1）：不查询、计 `fallbackTickUnresolved`、走快照 —— 不把 −1 当 tick 传进去。

### 3.3 flag 语义
未置位 = **不可读**：life/observerMode 保持 −1（不写 0）；origin / viewOffset / angles 未置位就拒绝这一行（`miss=origin-missing` / `offset-missing` / `angles-missing`），绝不把“没读到”当 0。

### 3.4 为什么本语料恒 `flags=25`（阻断命中路径的实测事实）
- 实测：pov_f12 的 tick 2177 / 4203 / 10617 / 19831 / 22203 与 STV 全部 85198 行，`flags` 恒 25（=1+8+16），`view_offset_z` 恒 0.000000，`angles` 恒 0,0,0。
- 读代码定位原因：builder（`native/src/demo_header_camera.cpp:114-130`）用 `readVectorRanked` 读**整向量** `m_vecViewOffset` / `m_angEyeAngles`；而 `readVectorRanked`（同文件 `:52-72`）只在“底座属性存在且是 VectorXY”时才去找 `<base>[2]` 扁平兄弟。`m_vecViewOffset` / `m_angEyeAngles` 在本引擎是**扁平标量**（N12-A 已记录：`main.cpp:502-528` 的 `readEyeOffsetZ` 直接按 `m_vecViewOffset[2]` 读，正是为此），底座不存在 ⇒ `complete=false` ⇒ flag 不置位。
- 该文件是第一步产物，本轮约束禁止修改，因此**没有为了证据好看去改它**（§附录 B 第 1 条）。

### 3.5 identity mismatch：拒绝，不接受
- 理由：SetView 与 PacketEntities 在同一个包里的先后，第一步实测 **0 样本（UNMEASURED）**。行描述的是“捕获时的视图目标”，与当前 lastViewEntity / target 不符时用它，等于把相机放进别人脑袋并印成本人的。
- STV 实测：1115/1115 全部 mismatch（行 entity=1，target=2），全部走快照。
- 自审修过一个**只影响可读性**的缺陷：relay 新行原先打印“接受行的 rowTick/flags/camEntity”，被拒时恒为 −1/0/−1，会把“查到并拒绝”读成“根本没有行”。现在打印**查到的行**（rowTick=reqTick、flags=25、camEntity=1），并新增 `used=0/1` 与 `rowAge`。

### 3.6 offsetAge 语义与 accept.py 会计恒等式的**潜在**冲突（留给 lead 决定）
- frozen 行：`offsetAge = ageTick − offsetTick`。快照路径 `ageTick = resolvedSceneTick`（A1/A2/A3 口径不变，实测 343 / 3540 / 0 与文档一致）。相机路径 `ageTick = 请求的 scene tick` ⇒ `offsetAge = 0`。
- `accept.py:1143-1144` 断言 `resolved_server == offsetTick + offsetAge`，`:1160` 不成立即 FAIL。相机路径命中时 `offsetTick` 是 scene tick（22203）、`resolved_server` 是快照 tick（19831）：0+22203 ≠ 19831 ⇒ **会 FAIL**。
- 本轮 0 次触发（§3.4）所以没出现；第三步一旦让 flags 到位必须同时定口径：或让 accept.py 认两条路径，或在相机路径打印“相对快照 tick 的负年龄”（19831−22203 = −2372，会计恒等式成立但读起来是负数）。**我没有为了让未来门禁过而改动 frozen 行的口径。**
