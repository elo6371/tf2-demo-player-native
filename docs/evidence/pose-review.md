## 这一层在测什么

机器判据（`scripts/rig-*`）能说的只有「144 个不同的骨骼矩阵在播放期间出现」「同一 tick 冻结到同一姿态」。
它们说不了**屏幕上的角色是不是摆对了** —— 骨骼顺序错、肢体镜像、帧不推进，这些计数器全都照样满意。
所以这里做的是人要看的东西：每个 (实体, 姿态) 一帧 PNG，相机锁在该实体上，配上机器读数。

按 W3 的要求，图上必须**至少有一个已知会错**的帧，否则「全都对」没有意义。负对照通过探针自己的代理层注入，
产品代码一行不改（`src/` 在画面探针里只读）：

| 模式 | 注入内容 | 应当表现为 |
|---|---|---|
| `--fault=asset` | 把某兵种的整套模型（mdl+vvd+vtx+动画表）换成另一兵种 | 屏幕上是另一个兵种 |
| `--fault=rig` | 只换动画表，网格不换 | 网格对、序列数据错 |
| `--fault=sequence` | 把该兵种自己的动画表截断 | 动画解不出来 |

**注入点必须是 loose 文件层**：`src/assets/localresources.ts` 的 `readLayer()` 先问 loose 目录、抛错才落 VPK。
而 `tf/models/` 在磁盘上根本不存在 —— 所有兵种模型都在 `tf2_misc_dir.vpk` 里 —— 所以只答
`/file?path=models/player/scout.mdl` 的注入**永远不会被请求**，跑出来和「对照通过」一模一样。
必须同时合成 `models` 与 `models/player` 两级 `/list` 应答，注入才可达。这是上一轮踩过的坑。

## 根因：`fromQuaternion` 把旋转矩阵写成了转置

修正前九个兵种**全部**被画成变形几何。这不是缺件：材质在、武器在、三角形数完整、`glError` 全 0。
是骨骼蒙皮错位。定位过程如下，判据不靠推理，靠 Valve 自己写在文件里的数据。

### 判据一：`mstudiobone_t.poseToBone` 就是「游戏里已知的姿态」

`source-model.ts` 原本在 `fromQuaternion` 上方写着这两种形式互为转置、**「这里的数据无法在两者间判定」**，
并列出「能定案的那项测试：拿一个游戏里已知的姿态，逐骨骼比对」。
`mstudiobone_t.poseToBone`（偏移 96，12 个 float）**就是那个姿态** —— 它是 Valve 自己存的绑定逆矩阵，
所以 `inv(W_bind)` 必须逐元素等于它。

### 判据二：根骨骼单根就够（排除层级顺序的干扰）

根骨骼没有父级，所以「子骨骼是否总排在父之后」这一条**不可能**影响它。以侦察兵 `bip_pelvis` 为例
（`quat=[0.9845, 0, 0, 0.1752]`）：

```
文件 poseToBone 行主序 = [1.000, 0, 0, 0,  0, -0.939,  0.345, 44.990,  0, -0.345, -0.939, 14.795]
inv(W_std)             = [1.000, 0, 0, 0,  0, -0.939,  0.345, 44.990,  0, -0.345, -0.939, 14.795]   残差 1.04e-6
inv(W_code)            = [1.000, 0, 0, 0,  0, -0.939, -0.345, 43.863,  0,  0.345, -0.939,-17.861]   残差 3.27e+1
```

### 原来那个「无法判定」的结论错在哪

原文的理由是：「这个骨架的绑定四元数大多绕单轴，那些项带 `w` 的分量为零，两种形式给出同一矩阵」。
**这个前提不成立。** 绕单轴时，**存活下来的恰好就是带 `w` 的项**。绕 X 轴旋转时两种形式只在
`(1,2)` 与 `(2,1)` 两个非对角元上差 `2*x*w`；`bip_pelvis` 的 `2*x*w = 2×0.9845×0.1752 = 0.345`，
取逆之后变成 **33 个单位的平移误差**。所以「绑定姿态无法判定」是错的，绑定姿态单根就能判定。

另一半理由（网格侧：60 条动画里两个符号各让头骨落在自己的顶点簇内 27 / 32 次）是**判据力度不够**，
不是「数据无法判定」：它问的是「关节点是否落在一团顶点里」，而一个转置过的骨架**照样能落进去**。

### 判据三：姿态即绑定姿态的那些动画

### 已排除的嫌疑（都查过，都不是）

- **骨骼数上限**：九个兵种 `numbones` 73–92，**全部 < `buildBoneSkinMatrices` 的 `maxBones = 128`**。
- **VVD 顶点记录**：48 字节；权重 @0/4/8、骨骼索引 @12/13/14、`numbones` @15；取
  `min(3, byte@15)` 个影响并归一化、第 4 分量权重 0 —— **与 SDK `mstudiovertex_t` 逐项一致**。
- **VAO 属性**：`aBoneIndices` 是 `uvec4`，用 `vertexAttribIPointer` 绑定（不是 `vertexAttribPointer`），正确。
- **顶点着色器蒙皮公式**：`w.x*B[i.x] + w.y*B[i.y] + w.z*B[i.z] + w.w*B[i.w]`，正确。
- **`buildBoneSkinMatrices` 结构**：`out` 先填单位矩阵、只对 `bone < limit` 写
  `current * invertAffine(bind)`、行主序 3x4 转列主序 4x4 —— 转置映射逐元素核对无误。
- **`composeSkeleton` 的「子骨骼总在父之后」假设**：成立。用 `parent * local` 组合能复现 `poseToBone`
  到 2.4e-5；换成 `local * parent` 是 9.6e1。
- **跨文件骨骼匹配**：动画文件与渲染模型的同名骨骼绑定值**逐位相同**（pos / quat 最大差 0.0000）。
  侦察兵渲染模型 78 根、动画文件 76 根，多出的 2 根在动画文件里没有同名骨骼 ——
  按格式含义保留绑定矩阵，正确。
- **`matrix3x4_t` 的展开方向**（一度怀疑 `attachment.local` 被按错方向喂进 `multiplyMatrices`）：
  **文件是行主序**（`poseToBone` 按行主序比对上 2.4e-5，按列主序是 7.4e1），
  与 `multiplyMatrices` 一致，**这条嫌疑排除**。
- **模型空间 → 世界空间**：`modelMatrix` 把模型 +Y 映到世界 +Z；绑定盒 Y 跨 0–82 说明模型空间 Y 朝上。
  映射正确，屏幕上的横向观感来自跟随相机的俯角与角色自身的蹲姿，不是朝向错误。

## 仪器局限（必须记账，否则读数会被读得比实际更强）

1. **逐帧聚合读数判不出这个缺陷。** 角色只占画面很小一块：修正后的侦察兵帧
   `dom=0.1580 mean=51.52`，把它的模型换成重装兵的同一帧 `dom=0.1578 mean=51.28` —— 几乎不动。
   所以 `meanLuminance` / `fractionNotClear` / `dominantColourShare` **只用来证明「这一帧不是空的、
   `glError` 为 0、相机与时钟在推进」，不用来判定姿态**。判定是**人看画面**。
   （这三条读数仍是必要的：它们抓得住「模型没上屏」「相机没跟上」这类失败。）
2. **注入会扰动探针的节奏。** 修正前那轮对照里 `entity-007-pose-1` 的
   `mean` 从 51.36 跳到 109.11，而相机与时钟读数完全相同。原因是注入多了 4 次往返（含 4.08 MB 的动画表），
   改变了探针基于挂钟的推进节奏，进而扰动**世界资源的异步流式加载**。
   **不要把那一帧的聚合数字读成「角色变了」。**
3. **跟随相机没有墙体检测。** `src/render/camera.ts` 的 `followDistance = 220` / `followHeight = 90`
   是硬编码且无 UI 控件，室内必然穿墙 —— `entity-002`（士兵）四个姿态全落在几何体内，**不可判**。
   这是产品缺陷，不是探针缺陷，本轮不改（`src/` 只读）；探针如实标 `不可判` 而不猜。
4. **注入只替换 loose 文件层。** 原生目录选择器那条路径没有被本探针证明。
5. **探针用 `--no-sandbox` 启动**，是本机环境让步（本机渲染器沙箱起不来，见
   `docs/evidence/export-filesystem.md` 末节），不是产品设置。
6. **与游戏逐帧一致这件事未验证。** 本机没有 TF2 的参照渲染，「对」的判据是
   「可辨、连贯、武器挂在手上」，不是「与游戏内同一帧像素一致」。
   **绑定姿态**可以逐骨骼比对（`poseToBone`），**任意动画帧**没有可比对的参照物。

## 未闭环

1. **`a_reference` / `b_reference` 两种约定下都不等于绑定姿态。** 侦察兵 `a_reference` @15：
   修正前 [83.3, 84.3, 87.7]、修正后 [53.1, 25.2, 67.9]，而绑定盒是 [30.8, 81.7, 22.2] ——
   修正后是**刚性的 90° 绕 X 旋转**（绑定盒的 Y/Z 互换），不是散架，但也不是绑定姿态。
   要么 TF2 的 `@ref` 本来就不是绑定姿态，要么 `decodePose` 还有第二层问题。**未查完。**
2. **`rootVector` 对根骨骼位置通道的换序**（`src/assets/source-model.ts` 的 `RAWPOS`/`ANIMPOS` 分支）
   是源码里自己标注为「推断」的一处。本轮没有推翻它，也没有验证它。
3. **W3 要求的三份只读文件**（`src/engine/reconstruct.ts`、`src/render/renderer.ts`、
