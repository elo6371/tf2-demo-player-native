## 3. 构建过程中撞到的三件事（都会让「构建成功」变成假话）
1. `ops_edit_file` 在 Windows 上**保留 mtime**，NMAKE/CMake 因此认为源码没改。第一次构建产物 sha256 变了、bytes 没变、符号没有（上条假 exe）。之后每次构建前先 `find build-nmake/CMakeFiles/{tf2_core.dir,tf2_demo_native.dir,demo_open_probe.dir} -name '*.obj' -delete`，或 `touch` 源文件。
2. 新 TU 只登记在 `tf2-libraries.cmake` 不够：该文件被 include，CMake 靠 mtime 判断要不要重配，mtime 被保留 ⇒ 新源文件永不进 `tf2_core`，链接报 `error LNK2019: 无法解析的外部符号 "void __cdecl tf2::native::stampCameraTickRow(...)"` / `error LNK1120: 2 个无法解析的外部命令`。显式重跑一次 configure 后消失。
3. 构建自带 D-90 身份闸（`native/cmake/gen-build-stamp.cmake:283-302`）：存在未跟踪的编译输入就直接 `FATAL_ERROR`（「identity that silently omits an input must not be produced」）。为让门禁通过，我对**单个文件**执行了 `git add -- native/src/demo_header_camera.cpp`（未 commit）。

## 5. 包内消息顺序：实测到什么、没实测到什么

- 三个顺序计数器在 pov_f12 全是 0：`camera_packets_with_set_view=0`、`camera_set_view_before_entities=0`、`camera_set_view_after_entities=0`。
- 同时 `data_packets=300643` 全部经过盖章点（`camera_rows + camera_rows_no_target = 300643`），所以「0 个包同时含 SetView 与 PacketEntities」是**测出来的**，不是没跑到。
- demo 自己报 `setview_count=1`、`last_view_entity=9`。两者合起来 ⇒ 本 demo 唯一的 SetView 落在**不盖章的 entry**（signon 段）。
- 因此：**「包内 SetView 与 PacketEntities 的先后」在 pov_f12 上仍是 UNMEASURED**——计数器通路验证过（三处都在盖章路径上、且被 30 万个包走过），但没有样本。风险状态不因本轮读数关闭。
- 实现按「不假设顺序」写：捕获值只作为差异证据，最终身份以包边界末态为准（§0 的目标索引取法）；顺序真的出现时，最坏情况是 `cameraIdentityMismatch`/`cameraIdentityRebuilt` 非零，而不是行里存了过期目标。

## 6. 没证明什么（NOT VERIFIED / UNMEASURED）

- **产品侧 Q5 的实际表现未观测**：本轮只构建、未运行产品 exe（硬规则），所以 `g_sceneResolvedServerTick = -1` 之后画面/relay 年龄/绘制门禁的运行时行为 **NOT VERIFIED**。只核了静态读取点（4 处，均已对 -1 短路）。
- **门禁未跑**：`demo-clock-check.sh` 的 A3 断言本轮 **NOT RUN**。`snapshot_stale=-1` 与产品同口径是它的前提，不是我跑过它。
- **身份重建路径 0 次触发**：`camera_identity_rebuilt=0`、`camera_identity_mismatch=0`，所以「末态重建」这条代码路径在本 demo 上 **NOT EXERCISED**（逻辑存在、编译过，但没有运行证据）。
- **容量淘汰路径 0 次触发**：`camera_rows_dropped=0`，`erase(begin())`（每行 O(n)）**NOT EXERCISED**；`maxSamples=400000` 与 ~300k 行的边界未实测。
- **`cameraRowTickMismatch` 的语义边界**：它计的是「捕获时 `readPacketEntities` 收到的流内 packetTick ≠ 包边界 `finalNetworkTick`」，本 demo 实测 0。而「行 tick == `packetServerTicks[row]`」是**构造相等**（同一个 `stream.finalNetworkTick` 赋给两处），不是独立测量；这句话写在这里，避免把构造相等读成验证。
- **跨 demo 覆盖**：只测了 pov_f12 一份。stv_f12 / upward 的 dem 路径未能定位，**NOT TESTED**；不同 recording 下 SetView/PacketEntities 同包、以及 25 个无 PacketEntities 的包在别的 demo 上的分布，**UNKNOWN**。
- **性能代价**：只观测了内存（16.8 MB / 300642 行），**未测**采集耗时（`measureAppendCost` 未接入探针）。
- **同 tick 多行的查询语义**：`camera_duplicate_tick_rows=24`（与 `server_tick_stalls=23` 同量级），查询取该 tick 的**最后一行**（`upper-1`）。这个选择是契约，但「最后一行就是该 tick 的最终状态」只在 pov_f12 的 24 处同 tick 行上成立与否 **NOT VERIFIED**（没有逐行核对）。
- **默认关闭意味着产品读数为 0**：`CameraTrackLimits::enabled=false`，不给探针开关时 `camera_rows=0`。这是构造结果，不是「没有发生」。
